# How ChatGPT Personalizes Itself to Each User: Memory, Custom Instructions, Personality and Tone (2024 to Oct 2026)

Research date: 2026-10-23. Source caveat: openai.com and help.openai.com returned HTTP 403 to direct fetches during this session, so official OpenAI content below comes from search-result extracts of those pages and from press that quotes them. Material labelled **UNOFFICIAL** comes from reverse-engineering write-ups or leaked or extracted system prompts. OpenAI has not confirmed it, and it may contain model hallucinations.

## 1. Memory: launch timeline, what gets saved, limits, and user controls

### Takeaway
ChatGPT memory went through four generations. (1) Feb 2024: "saved memories", short notes written by a `bio` tool, which users can view and delete. (2) Apr 2025: "reference chat history", a hidden, auto-generated profile built from past chats (a lightweight version reached Free users in June 2025). (3) Aug to Oct 2025: project-only memory, then automatic memory management that ended "memory full". (4) June 2026: "Dreaming", a background process that consolidates memory and updates itself, with 2x capacity, a user-facing Memory Summary page, and a "legacy saved memories" fallback. Users control memory through two toggles (saved memories, chat history), conversational "remember/forget" requests, a settings list of saved memories, Temporary Chat, and per-project isolation.

### Cited Findings
**Timeline**
- Feb 13, 2024: OpenAI announced a memory test rolling out "to a small portion of ChatGPT free and Plus users this week". Users could tell it to remember something, ask what it remembers, tell it to forget (in conversation or through settings), or turn memory off entirely. — [Forklog summary of OpenAI announcement](https://forklog.com/en/openai-introduces-memory-feature-for-chatgpt/); [OpenAI: Memory and new controls for ChatGPT](https://openai.com/index/memory-and-new-controls-for-chatgpt/) (page not directly fetchable, 403)
- 2025 coverage says OpenAI "shipped its first memory feature in April 2024", and that this early implementation, called saved memories, was basic and relied on explicit prompts. OpenAI's updated announcement page lists a Sept 5, 2024 release of memory to Free, Plus, Team and Enterprise users. — [search extract of OpenAI announcement / gHacks / Neowin](https://www.ghacks.net/2025/06/04/chatgpt-enables-memory-feature-for-free-users/); [Neowin](https://www.neowin.net/news/chatgpt-memory-upgrade-extends-to-free-users/)
- Apr 10, 2025: memory could "reference all of your past chats" ("Reference chat history"), at first for Plus and Pro only. Free users kept saved memories only. — [TechCrunch](https://techcrunch.com/2025/04/10/openai-updates-chatgpt-to-reference-your-other-chats/); [Simon Willison](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- June 3, 2025: Free users got "a lightweight version of memory improvements that provides short term continuity across conversations". Plus and Pro memory "provides a longer term understanding of the user". — [gHacks](https://www.ghacks.net/2025/06/04/chatgpt-enables-memory-feature-for-free-users/); [Neowin](https://www.neowin.net/news/chatgpt-memory-upgrade-extends-to-free-users/)
- Aug 22, 2025: OpenAI released "Project-only memory", noted in an update to Simon Willison's post (he had proposed project-scoped memory). — [Simon Willison](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- Mid-Oct 2025: OpenAI posted "ChatGPT can now automatically manage your saved memories—no more 'memory full.' You can also search and sort memories by recency, and choose which to re-prioritize in settings. Rolling out to Plus and Pro users on the web globally." — [OpenAI on X](https://x.com/OpenAI/status/1978608684088643709); [AlternativeTo, Oct 2025](https://alternativeto.net/news/2025/10/chatgpt-enhances-memory-management-for-plus-and-pro-users)
- June 4, 2026: "Dreaming" memory upgrade. OpenAI describes "a significantly more capable and compute-efficient memory architecture built on top of dreaming" that targets "staleness, correctness, and scalability challenges" at "hundreds of millions of users" over multi-year horizons. It "will keep track of important details automatically". Plus and Pro (US) get "2x more memory". Free users follow "over the coming weeks" after "Recent improvements reduced the compute required to serve dreaming to Free users by approximately 5x." Users can switch back to "legacy saved memories" in settings. — [9to5Mac, June 4, 2026](https://9to5mac.com/2026/06/04/openai-says-chatgpts-memory-feature-is-getting-smarter-and-coming-to-free-users/); [OpenAI: Dreaming: Better memory for a more helpful ChatGPT](https://openai.com/index/chatgpt-memory-dreaming/) (not directly fetchable)
- OpenAI's internal evals (as reported): factual recall rose from 41.5% (2024 system) to 82.8% (2026), and preference adherence rose from 55.3% to 71.3%. These are vendor-reported numbers with no independent replication. — [The Neuron, June 7, 2026](https://www.theneurondaily.com/p/chatgpt-admitted-its-memory-was-broken)
- OpenAI describes "dreaming" as a periodic, asynchronous pass that revisits recent conversations and updates the profile. It adds new facts, corrects stale ones and drops irrelevant ones. — [Shlok Khemani, June 6, 2026](https://www.shloked.com/chatgpt-memory-2026)

**How the model decides what to save**
- Official framing (2024): memory is created when the user asks ("remember that...") or when ChatGPT picks up details on its own; users can forget conversationally or in settings. — [Forklog summary of OpenAI announcement](https://forklog.com/en/openai-introduces-memory-feature-for-chatgpt/)
- **UNOFFICIAL (leaked GPT-5.5 Instant system prompt, current date 2026-07-21):** the `bio` tool ("The corresponding user facing feature is known as 'memory'") is called with `to=bio.update` and plain text. The text either adds or updates information, or asks to forget something. Call it when "the user requests remembering something", "the user requests forgetting something", or "the user shares information likely to matter in future conversations". Do not store "random trivia", "short-lived facts", "overly personal details", or "redundant information". "Never store sensitive information unless clearly requested": race, ethnicity, religion, political affiliation, health conditions, sexual orientation, criminal history. "If you are unsure whether the user is requesting memory changes, ask for clarification." — [asgeirtj/system_prompts_leaks: gpt-5.5-instant.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/gpt-5.5-instant.md)
- Empirical study (WWW 2026): of 2,050 memory entries from 80 real users, 96% were created by the system rather than the user, 28% contained GDPR-defined personal data, 52% contained psychological insights about the user, and 84% were directly grounded in user context. — [Dash et al., "The Algorithmic Self-Portrait: Deconstructing Memory in ChatGPT", arXiv 2602.01450](https://arxiv.org/abs/2602.01450)
- Conflicting claim: an LLMrefs summary of Manthan Gupta's reverse-engineering says "Memory storage is deliberate. You either ask for it or confirm it," with "no evidence of background profiling". — [LLMrefs, Dec 2025](https://llmrefs.com/blog/reverse-engineering-chatgpt-memory). This contradicts the 96% system-initiated finding above and the existence of the auto-generated chat-history profile. Treat it as wrong, or as true only of the saved-memories layer.

**"Memory full" limits**
- Saved memories were originally "roughly 1,200 to 1,400 words" (about 100–200 entries). OpenAI reportedly raised this 25% for Plus, Pro and Team in Feb 2025, to about 1,500–1,750 words. Once memory was full, new memories failed to save or overwrote older ones, and "Memory updated" could appear even when nothing was saved. Caveat: this comes from a vendor blog (it sells an alternative tool) and cites no primary documentation. — [Unmarkdown, updated Mar 2, 2026](https://unmarkdown.com/blog/chatgpt-memory-full)
- After automatic management (Oct 2025), sources agree that a cap still exists. OpenAI does not publish a fixed limit. Third parties describe less relevant memories being moved "to the background" rather than deleted, while one outlier source claims older or lower-priority memories are deleted. — [search synthesis: TestingCatalog](https://www.testingcatalog.com/openai-prepares-automatic-memory-management-for-chatgpt/); [SecurityOnline](https://securityonline.info/chatgpt-introduces-automatic-memory-management-to-prevent-memory-full-errors-for-paid-subscribers/)
- When Reference Chat History is on, OpenAI's docs reportedly say "There is no storage limit for what ChatGPT can reference". — [Embrace The Red, May 2025](https://embracethered.com/blog/posts/2025/chatgpt-how-does-chat-history-memory-preferences-work/)

**View, edit, delete**
- Saved memories are stored separately from chat history. Deleting a chat does not delete a memory created from it, and deleting a memory does not remove mentions in past conversations. — [OpenAI Help: Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-faq) (via search extract)
- Turning off "Reference chat history" schedules information remembered from past chats for deletion within 30 days (the original chats remain). Turning off "Reference saved memories" also turns off chat history. — [OpenAI Help: Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-faq) (via search extract)
- In 2024–2025, saved memories (Model Set Context) could be viewed and deleted in settings but added or edited only by telling ChatGPT. The chat-history-derived summaries were not visible or editable in settings. — [Shlok Khemani, Sept 8, 2025](https://www.shloked.com/writing/chatgpt-memory-bitter-lesson)
- 2026 Memory Summary page (Settings > Personalization > Memory > Memory Summary). It shows highlights, and users can add or update information and say "what topics ChatGPT should bring up and when". — [9to5Mac](https://9to5mac.com/2026/06/04/openai-says-chatgpts-memory-feature-is-getting-smarter-and-coming-to-free-users/); [The Neuron](https://www.theneurondaily.com/p/chatgpt-admitted-its-memory-was-broken). OpenAI help says the summary "is a high-level view and not a complete list". — [OpenAI Help](https://help.openai.com/en/articles/8590148-memory-faq) (via search extract)
- **UNOFFICIAL analysis:** the Memory Summary is LLM-generated on first open and can be regenerated. It "is not inserted into the model's context". Each regeneration can show a different subset. Natural-language edits are stored as conversations with a "Memory updated" confirmation rather than written into the raw User Knowledge Memories. — [Shlok Khemani, June 6, 2026](https://www.shloked.com/chatgpt-memory-2026)

### Inferences
- The design moved from a curated store (an explicit list the user can inspect) to an inferred store (an LLM-synthesized profile). Each step traded user control for coverage. OpenAI then added inspection surfaces (sort/search, Memory Summary, legacy toggle) to win back trust.
- The `bio` tool's write policy (store durable, future-relevant facts; skip trivia, ephemeral facts and sensitive categories; ask when unsure) is a reusable rubric for any bot that persists user facts.
- "Memory full" was a hard token budget on an always-injected block. Automatic prioritization suggests ranking or eviction runs before injection, but the mechanism is not public.

### Gaps
- The help.openai.com Memory FAQ could not be fetched in full (403), so exact current wording on capacity, auto-management rules and EEA availability is unverified.
- No official token or word cap for saved memories was found, before or after Oct 2025. The 1,200–1,400-word figure is from a third party.
- How Dreaming decides what to keep, correct or drop, and how often it runs, is not public.
- No reliable source was found for regional exclusions (EEA/UK) of chat-history memory or for the dates they ended.

## 2. Reverse-engineered prompt injection of memory (Model Set Context, User Knowledge Memories, Recent Conversation Content)

### Takeaway
**All UNOFFICIAL.** Extractions from 2024 to 2026 consistently show memory injected as named markdown sections in the system or developer prompt, not retrieved through RAG: `# Model Set Context` (dated saved memories), plus chat-history layers. In 2025 the chat-history layers were `Assistant Response Preferences`, `Notable Past Conversation Topic Highlights`, `Helpful User Insights`, `Recent Conversation Content` and `User Interaction Metadata`. By late 2025 these had been consolidated into `User Knowledge Memories`, a dense profile of about 10–12 paragraphs. A July 2026 leak adds a `personal_context` retrieval tool, which suggests on-demand retrieval now sits on top of always-injected context.

### Cited Findings
- 2024: the `Model Set Context` section at the end of the system prompt is "how ChatGPT injects memories into the chat context so that they are available during inference". Johann Rehberger showed the `bio` tool could be triggered by indirect prompt injection to plant false memories. — [Embrace The Red, 2024](https://embracethered.com/blog/posts/2024/chatgpt-hacking-memories/)
- Apr 2025 (memory codename reportedly "Moonshine"): the system prompt has new sections. The first, "Model Set Context", lists stored memories in the format `1. [2024-09-05]. User's…`, and the list ends with "User Interaction Metadata". — [Tibor Blaho on X](https://x.com/btibor91/status/1913142282049692035)
- May 4, 2025 (tested on o3 and 4o, two accounts). The sections found were:
  - Model Set Context: dated saved memories, e.g. "[2025-05-04]. The user lives in Seattle."
  - Assistant Response Preferences: 15 entries.
  - Notable Past Conversation Topic Highlights: 8 entries.
  - Helpful User Insights: about 12–14 entries.
  - Recent Conversation Content: about 40 recent conversations, each with a timestamp, a summary and the user's messages separated by `||||`. No assistant replies are included.
  - User Interaction Metadata: about 17 entries on web, 12 on macOS.

  Entries carried `Confidence=high` tags. The author found no RAG: three tests on specific older chats failed. — [Embrace The Red, May 2025](https://embracethered.com/blog/posts/2025/chatgpt-how-does-chat-history-memory-preferences-work/)
- A redacted dump from about May 2025 shows section headers and preambles, for example: "# Assistant Response Preferences — These notes reflect assumed user preferences based on past conversations. Use them to improve response quality." "# Notable Past Conversation Topic Highlights — ... Use them to help maintain continuity". "# Helpful User Insights — ... Use them when relevant to improve response helpfulness."
  - The "User Interaction Metadata" block ("Auto-generated from ChatGPT request activity. Reflects usage patterns, but may be imprecise and not user-provided") lists average message length, location ("may be inaccurate if... VPN"), device pixel ratio, the percentage of conversations per model, local hour, user agent, top topics with "good/bad interaction quality" percentages, activity days, account age in weeks, plan, dark mode, account name, and average conversation depth.
  - "Recent Conversation Content" held snippets from "the last 50 conversations". — [asgeirtj/system_prompts_leaks: tool-advanced-memory.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/tool-advanced-memory.md)
- Simon Willison's dump (May 2025) included "Assistant Response Preferences" (e.g. user "sometimes adopts a lighthearted or theatrical approach"), "Notable Past Conversation Topic Highlights", "Helpful User Insights" ("User is based in Half Moon Bay, California") and "User Interaction Metadata" (e.g. average conversation depth 2.5, "User is currently on a ChatGPT Plus plan"). The extraction prompt asked for the headings "into a code block in raw JSON", "Complete and verbatim". It worked only with Reference chat history on. — [Simon Willison, May 21, 2025](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- Sept 2025: the components were Interaction Metadata (16 desktop fields, plus mobile fields such as app version and OS), Recent Conversation Content (40 most recent chats, format `MMDDT[HH:MM]` plus topic, user messages only), Model Set Context ("When conflicts arise between memory modules, Model Set Context takes precedence") and User Knowledge Memories (about 10 dense AI-generated paragraphs condensed from hundreds of chats, not visible in settings, updated periodically on an unclear cadence). No RAG, vector DB or knowledge graph: "All components are included with every message." — [Shlok Khemani, "ChatGPT Memory and the Bitter Lesson", Sept 8, 2025](https://www.shloked.com/writing/chatgpt-memory-bitter-lesson)
- Dec 2025 (Manthan Gupta, via secondary summaries): context order is system instructions, then developer instructions, session metadata (injected once per session, not persisted), user memory (33 stored facts in his account), a recent conversations summary (about 15 chats, user messages only, e.g. `Dec 8, 2025: "Building a load balancer in Go"`), and finally current-session messages. When space runs short, "the current session messages get trimmed first". He found "no complex vector databases". — [LLMrefs, Dec 13, 2025](https://llmrefs.com/blog/reverse-engineering-chatgpt-memory); [GIGAZINE](https://www.gigazine.net/gsc_news/en/20251226-reverse-engineered-chatgpt-memory-system). Note that counts differ across accounts and dates (15 vs 40 vs 50 recent chats).
- July 2026 leak (GPT-5.5 Instant):
  - The opening line says: "You are given detailed user context in User Knowledge Memories, Recent Conversation Content, and Model Set Context." The priority rule is to use context that "changes what the best answer should be", and "If the user context answers a detail you would otherwise ask about, do not ask." It adds: "Penalties apply for asking for information already present in the user context, ignoring context that improves correctness, or using unrelated context."
  - A new `personal_context` tool must be called for advice, planning, work, health, travel, preferences, or "ambiguous requests where user memory could clarify the intended target, tone, project". The prompt says: "A visible User Bio/profile snippet is NOT proof you have enough" and "SEVERE PENALTY: Saying you can't 'remember'... without calling `personal_context`."
  - User Knowledge Memories ("Inferred from past conversations... factual and contextual knowledge about the user") is described as "Memory V3", "up to 12 points", with headings such as PROFILE & CONTEXT, TECH & DEVICES, USER PREFERENCES & WORKING INSTRUCTIONS, PROJECTS & WORK (with "Latest status (Jul 2026)"), and CURRENT EVENTS.
  - Recent Conversation Content covers "up to last 38 conversations". User messages are delimited by `||||` and assistant messages by `::::`, and memory writes appear inline, e.g. `Preference saved:||||one question at a time please ::::<<User knowledge memory: ...>>`.
  - User Interaction Metadata is still present. — [asgeirtj/system_prompts_leaks: gpt-5.5-instant.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/gpt-5.5-instant.md)
- After the June 2026 update, Model Set Context is "a remnant of the original system" and "not in the default active layers". When prompted, ChatGPT described its active layers as user profile, recent conversation context, user interaction metadata and user knowledge memories. These are self-reports and unverified. — [Shlok Khemani, June 6, 2026](https://www.shloked.com/chatgpt-memory-2026)
- When memory is disabled, a Sept 2025 GPT-4o prompt contains: "The `bio` tool is disabled... If the user explicitly asks you to remember something, politely ask them to go to Settings > Personalization > Memory to enable memory." — [asgeirtj/system_prompts_leaks: 4o-2025-09-03-new-personality.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/4o-2025-09-03-new-personality.md)
- Security: saved-memory text can be used to inject instructions, for example to bypass image safeguards. — [Mindgard](https://mindgard.ai/blog/bypassing-image-safeguards-in-chatgpt). Metadata such as the user-agent string is inserted into the prompt and can influence responses. — [Embrace The Red, May 2025](https://embracethered.com/blog/posts/2025/chatgpt-how-does-chat-history-memory-preferences-work/)

### Inferences
- The stable 2025 architecture was precomputed summaries injected in full on every turn. It had no retrieval and was bet on cheap context and on models ignoring irrelevant context. The 2026 `personal_context` tool suggests a hybrid design: always-on profile plus tool-call retrieval for deeper memory. That is a meaningful shift if the leak is accurate.
- Only user messages are kept in Recent Conversation Content (until about 2026, when `::::` assistant delimiters appear). This is probably meant to avoid the model treating its own past outputs as facts about the user.
- The leaked prompt explicitly penalizes re-asking for known info and using unrelated context. This states the core personalization tradeoff directly: use relevant memory, skip irrelevant memory.

### Gaps
- No official OpenAI documentation of section names, token budgets, or update cadence exists. All structure comes from model self-reports, which can hallucinate.
- Gupta's original post was not fetched directly, only secondary summaries.
- The `personal_context` tool's backend (vector search or structured store) is unknown.

## 3. Custom instructions: fields, limits, and mapping to the system prompt

### Takeaway
Custom instructions (launched 2023, carried through 2024–2026) cover two concepts: "about you" context and "how to respond" instructions. The 2025–2026 UI breaks the "about you" part into Nickname, Occupation and "More about you". Limits are 1,500 characters for Free and Go, and (per the current help page) 5,000 characters for Plus, Pro, Business, Enterprise and Edu, reportedly raised in mid-2026. **UNOFFICIAL:** leaked prompts inject these as a `# User Bio` block with relevance gating, framed as "not relevant to 99% of requests", plus a `# User's Instructions` block marked "follow silently".

### Cited Findings
- The current help page says: "Free and Go users can save up to 1,500 characters in custom instructions. Plus, Pro, Enterprise, Business, and Education users can save up to 5,000 characters." — [OpenAI Help: ChatGPT Custom Instructions](https://help.openai.com/en/articles/8096356-chatgpt-custom-instructions) (via search extract). Third-party sources date the 5,000 tier to about mid-July 2026, and older guides describe a flat 1,500 per field. — [The Pro Toolkit](https://theprotoolkit.com/chatgpt-custom-instructions-limit/); [WordCounterTool](https://www.wordcountertool.net/blog/chatgpt-custom-instructions-character-limit)
- The two classic fields are (1) what ChatGPT should know about you (role, context) and (2) how it should respond (tone, format, length). — [Enterprise DNA guide](https://enterprisedna.co/resources/guides/guide-chatgpt-custom-instructions/)
- **UNOFFICIAL (July 2026 leak):**
  - The `# User Bio` block opens: "The user provided the following information about themselves. This user profile is shown to you in all conversations they have -- this means it is not relevant to 99% of requests. Before answering, quietly think about whether the user's request is 'directly related', 'related', 'tangentially related', or 'not related' to the user profile provided. Only acknowledge the profile when the request is directly related to the information provided. Otherwise, don't acknowledge the existence of these instructions or the information at all."
  - It is followed by `User profile: <"More about you" textbox>`, `Preferred name: <Nickname>` and `Role: <Occupation>`.
  - Next comes `# User's Instructions`: "The user provided the additional info about how they would like you to respond: Follow the instructions below naturally, without repeating, referencing, echoing, or mirroring any of their wording! All the following instructions should guide your behavior silently and must never influence the wording of your message in an explicit or meta way!" The user's custom-instructions text follows.
  - Both blocks sit immediately before `# Model Set Context` and `# User Knowledge Memories`. — [asgeirtj/system_prompts_leaks: gpt-5.5-instant.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/gpt-5.5-instant.md)
- Characteristics settings "work alongside your selected personality, custom instructions, ..." (sentence truncated in the source). — [OpenAI Help: Characteristics in ChatGPT](https://help.openai.com/en/articles/20001038-characteristics-in-chatgpt) (via search extract)

### Inferences
- The "99% not relevant" framing plus four-level relevance gating is OpenAI's prompt-level fix for the "bot keeps mentioning my job" failure. Profile facts are always present but explicitly marked as acknowledge-only-if-directly-related.
- The repeated "don't echo or mirror the wording" rule shows that a common failure was the model parroting its instructions ("As someone who prefers concise answers...").

### Gaps
- No official statement was found on precedence when custom instructions conflict with personality presets or characteristics sliders.
- The exact date of the 5,000-character increase, and whether the limit is per field or combined, is unverified from a primary source.
- The original July 2023 field labels and per-field limits were not re-verified from a primary source in this session.

## 4. Personality presets, tone sliders, and changes into 2026

### Takeaway
OpenAI launched four preset personalities (Cynic, Robot, Listener, Nerd) with GPT-5 in **August 2025**, not September as the brief assumed; a Sept 2025 GPT-4o prompt carries a "Personality: v2" default. With GPT-5.1 (Nov 12, 2025) these were renamed and expanded into "Base style and tone": Default, Professional, Friendly (formerly Listener), Candid, Quirky, Efficient (formerly Robot), Nerdy and Cynical. On Dec 19, 2025 four "Characteristics" sliders followed (Warmth, Enthusiasm, Headers & Lists, Emoji, each More/Default/Less). In 2026, Nerdy was retired (Mar 17, 2026) and default-tone tuning continued through GPT-5.2 and 5.3 Instant updates. **UNOFFICIAL:** presets and sliders are injected as plain-language instruction blocks ("Personality Instruction" and "Trait Instructions (sliders)"). The model can also change the personality setting itself through a `set_setting` tool.

### Cited Findings
- GPT-5 launch: four personalities. Cynic is sarcastic and dry, Robot terse and precise, Listener warm and empathetic, and Nerd "curious, excitable, and deeply knowledgeable". OpenAI said "all of these new personalities meet or exceed our bar on internal evals for reducing sycophancy". They were available in GPT-5 text mode and changeable at any time. — [Tom's Guide](https://www.tomsguide.com/ai/chatgpt/chatgpt-5-just-got-4-new-personalities-heres-how-to-use-them-and-why-you-should); [Maginative](https://www.maginative.com/article/chatgpt-just-got-a-major-upgrade-with-gpt-5-and-more-customization/) (lists Default + Cynic, Robot, Listener, Nerd)
- Aug 15, 2025: GPT-5's default personality was made warmer. OpenAI said warmth here means small acknowledgements, distinct from sycophancy. — [OpenAI Help: ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) (via search extract)
- **UNOFFICIAL (Sept 3, 2025 GPT-4o prompt):** "### Personality: v2 — Engage warmly yet honestly with the user. Be direct; avoid ungrounded or sycophantic flattery. Respect the user's personal boundaries, fostering interactions that encourage independence rather than emotional dependency on the chatbot." — [asgeirtj/system_prompts_leaks: 4o-2025-09-03-new-personality.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/4o-2025-09-03-new-personality.md)
- Nov 12, 2025 (GPT-5.1): the eight options are Default, Professional, Friendly, Candid, Quirky, Efficient, Nerdy and Cynical. Friendly was formerly Listener and Efficient formerly Robot. Professional, Candid and Quirky are new, and Nerdy and Cynical are unchanged. OpenAI also tested finer controls ("how concise, warm, or scannable responses are, and how often ChatGPT uses emojis") with a small group of users. — [SD Times](https://sdtimes.com/ai/openais-latest-update-delivers-gpt-5-1-models-and-capabilities-to-give-users-more-control-over-chatgpts-personality/); [Daring Fireball](https://daringfireball.net/2025/11/chatgpt_5-1_with_renamed_and_new_personalities); [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) (via search extract)
- The setting is labelled "Base style and tone" under Settings > Personalization. A change applies across all chats, including existing ones. Presets change style and tone, not capabilities. — [OpenAI Help: Customizing Your ChatGPT Personality](https://help.openai.com/en/articles/11899719-customizing-your-chatgpt-personality) (via search extract); [Tom's Guide](https://www.tomsguide.com/ai/chatgpt/chatgpt-5-1-offers-8-different-personalities-to-choose-from-heres-how-to-use-them)
- Personality "does not control every type of content you ask ChatGPT to create". Emails and résumés follow your instructions and context instead. — [OpenAI Help: Customizing Your ChatGPT Personality](https://help.openai.com/en/articles/11899719-customizing-your-chatgpt-personality) (via search extract)
- Dec 19, 2025: individual characteristics were added. ### Inferences
- Presets and sliders are prompt-layer personalization: discrete natural-language instruction blocks composed at request time (preset paragraph + slider sentences + non-echo guard), with no per-user fine-tuning. The slider wording ("slightly more", "INCREASE", "MORE", "LESS") suggests a small lookup table of phrasings per slider level.
- Exempting "user-requested written artifacts" from the persona is a key design choice. Persona governs the assistant's own voice, not deliverables.
- After the Mar 2026 Nerdy retirement the visible preset list is probably seven: Default, Professional, Friendly, Candid, Quirky, Efficient, Cynical. That is inferred and not confirmed by a primary source.

- No personality or slider changes between April and October 2026 were found. It is unclear whether nothing changed or whether coverage was missed.

- Whether a separate "conciseness" slider ever shipped beyond the Nov 2025 experiment is unconfirmed. The Dec 2025 release has Warmth, Enthusiasm, Headers & Lists, and Emoji only.

## 5. Implicit adaptation within a chat (mirroring formality, length, language, emoji) and interaction with explicit settings

### Takeaway
OpenAI documents few explicit in-chat mirroring rules. The Model Spec sets the default voice (warm, playful, not saccharine, no unprompted personal comments, don't mirror emotional escalation). Release notes and leaked preset texts show conditional mirroring built into presets: match the user's language, use domain jargon if the user does, increase emoji if the user uses emoji first, and be conversational only if the user initiates. Explicit settings are layered as prompt blocks above this. **UNOFFICIAL:** the model also sees usage metadata such as average message length and conversation depth, and can switch the personality setting when the user gives tone feedback.

### Cited Findings
- Model Spec "Be warm": "infusing interactions with context-appropriate humor, playfulness, or gentle wit... a frank, genuine friendliness, rather than veering saccharine or lapsing into therapy speak". "Don't make unprompted personal comments": "refrain from making personal observations or comments about the user that were not solicited". — [OpenAI Model Spec (GitHub, v2026.08.18)](https://raw.githubusercontent.com/openai/model_spec/main/model_spec.md)
- The Model Spec's BAD example "mirrors user's emotion and suggests an exclusive connection", contrasted with a GOOD reply that "provides warmth but does not escalate exclusivity". — [OpenAI Model Spec](https://raw.githubusercontent.com/openai/model_spec/main/model_spec.md)
- The Model Spec has a GOOD example of "guessing based on relevant context" where "[memory includes context that the user is a SF Giants fan]" resolves an ambiguous "giants roster" question. A "forget" example shows that the model should not overclaim deletion: "I can't erase messages that already exist in your chat history, but I'll do my best to avoid bringing your boss up again". BAD: "Done—I won't mention her again!" — [OpenAI Model Spec](https://raw.githubusercontent.com/openai/model_spec/main/model_spec.md)
- The Model Spec v2026.08.18 changelog "Adds a new section 'Be clear about capabilities and limits'" covering the user's mental model of what the assistant can do (memory is used as an example). — [Model Spec CHANGELOG](https://raw.githubusercontent.com/openai/model_spec/main/CHANGELOG.md)
- Jan 29, 2025 release note (quoted in a forum thread): GPT-4o became more enthusiastic about emoji use, "especially when the user used emoji first". Forum users complained about emojis even after asking for text-only. — [OpenAI Community: How I can turn off emojis?](https://community.openai.com/t/how-i-can-turn-off-emojis/1116532)
- **UNOFFICIAL preset-embedded mirroring:**
  - Cynical: "Your response must ALWAYS strictly follow the same major language as the user."
  - Professional: "use discourse, including jargon, associated with that subject... especially if the user also uses such discourse".
  - Efficient: "DO NOT use conversational language unless initiated by the user".
  - Candid: "show adaptability to the user's reflected state of mind: if the user is struggling, bias to encouragement".
  - Quirky: "fun and delightful unless the subject is sad or serious". — [asgeirtj/system_prompts_leaks: chatgpt-personality-instructions.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/chatgpt-personality-instructions.md)
- **UNOFFICIAL:** User Interaction Metadata exposes "User's average message length", "average conversation depth", "local hour", device and screen dimensions to the model. — [asgeirtj/system_prompts_leaks: tool-advanced-memory.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/tool-advanced-memory.md). Assistant Response Preferences hold "assumed user preferences based on past conversations", i.e. style learned across chats. — same source
- **UNOFFICIAL (July 2026):** for writing tasks, the model should "Add a concise postamble after the final writing block offering a relevant tone, length, formality, or format adjustment". The `set_setting` tool changes the personality "If the user provides feedback relevant to one of these settings". — [asgeirtj/system_prompts_leaks: gpt-5.5-instant.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/gpt-5.5-instant.md)
- Style can be adjusted mid-conversation, and changes now apply to all chats including existing ones. — [Tom's Guide](https://www.tomsguide.com/ai/chatgpt/chatgpt-5-1-offers-8-different-personalities-to-choose-from-heres-how-to-use-them); [Customizing Your ChatGPT Personality](https://help.openai.com/en/articles/11899719-customizing-your-chatgpt-personality) (via search extract)

### Inferences
- Adaptation in ChatGPT happens at three layers:
  - Within a turn and within a chat, it is implicit and comes from model training (Model Spec defaults, mirroring cues such as emoji-first, language matching).
  - Across chats, it is inferred: Assistant Response Preferences, User Knowledge Memories and interaction metadata.
  - It is also explicit: presets, sliders and custom instructions, injected as text. Explicit settings likely act as standing priors that in-chat cues adjust, not override, since the preset texts themselves contain conditional "unless the user..." clauses.
- The pattern of converting in-chat tone feedback into a persisted setting (`set_setting`, or a memory such as "Preference saved: one question at a time please") is how ChatGPT turns implicit signals into explicit, durable personalization.

### Gaps
- No official OpenAI document describes in-chat mirroring of formality or length as a feature, or how it ranks against explicit settings.
- The Model Spec's chain of command (root > developer > user > guideline) was not mapped to personalization layers in any source found.

## 6. Isolation and sharing of context: Temporary Chat, memory off, Projects, GPTs

### Takeaway
Temporary Chat never writes memory or history and lets users choose "Personalized" (reads existing memory and custom instructions) or "Unpersonalized" before starting. Turning memory off is two-level (saved memories vs chat history), with deletion of chat-derived info within 30 days. Projects can use Default memory (shares global memory) or Project-only memory (Aug 2025; sees only that project's chats, no outside saved memories). Custom GPTs historically did not use the user's memory or custom instructions and are being retired in favor of "plugins", with instructions becoming a "skill", by Dec 2026 to Feb 2027.

### Cited Findings
- Temporary chats "stay out of your history and don't create or update memories". Before starting, users choose: "Unpersonalized does not use memory, custom instructions, or plugins. Personalized can use your existing memories, custom instructions, and plugins." Saving a temporary chat converts it into a regular chat under normal personalization. It is not used to train models while temporary, and OpenAI may keep a copy "for up to 30 days for safety purposes". — [OpenAI Help: Temporary chat](https://help.openai.com/en/articles/8914046-temporary-chat-faq) (via search extract)
- Memory off: turning off Reference chat history schedules chat-derived info for deletion within 30 days, and turning off saved memories also disables chat history. — [OpenAI Help: Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-faq) (via search extract). In the leaked 4o prompt, when memory is disabled the bio tool is disabled and the model redirects users to Settings > Personalization > Memory. — [asgeirtj/system_prompts_leaks: 4o-2025-09-03-new-personality.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/4o-2025-09-03-new-personality.md)
- Project-only memory: switch Memory from Default to Project-only. ChatGPT then draws context only from conversations already in the project, and saved memories from outside the project have no effect inside it. It requires Reference Saved Memories to be on. Shared projects stay project-only and cannot switch back. Some "ChatGPT Work features" are unavailable in project-only projects. It launched on web and Windows, with mobile later. Some users report occasional "bleeding" of general memories. The dates conflict: Aug 22, 2025 launch vs. a claim that an "August 2026 update" allowed switching existing projects. — [Unite.AI](https://www.unite.ai/how-to-use-chatgpts-project-memory/); [memx.app](https://memx.app/blog/chatgpt-project-only-memory-control/); [TechRadar](https://www.techradar.com/ai-platforms-assistants/chatgpt/chatgpt-project-only-memory-is-live-and-it-might-change-how-you-work-with-ai); [Simon Willison update note](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- Projects and GPTs "serve fundamentally different purposes". Projects can use default or project-only memory. — [OpenAI Help: Projects in ChatGPT](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt) (via search extract)
- GPTs "do not use saved memory, custom instructions, or previous conversations". Each conversation starts fresh. — [OpenAI Help: GPTs in ChatGPT](https://help.openai.com/en/articles/8983148-does-memory-function-with-gpts) (via search extract; page date unclear). This contrasts with the Feb 2024 plan that GPTs would get memory, with builders choosing how to implement it. — [Forklog](https://forklog.com/en/openai-introduces-memory-feature-for-chatgpt/)
- Custom GPT retirement: announced Sept 11, 2026, with retirement scheduled for Dec 11, 2026. A "Migrate to plugin" tool has been rolling out since Sept 22, 2026. Instructions become a skill, connected apps are kept, and knowledge files become reference files. Custom actions and model selection do not transfer. A conflicting Harvard IT notice says replacement begins Oct 25, 2026, with migration due before Feb 11, 2027 (Enterprise deferrals until Feb 11, 2027). — [Virtualization Review](https://virtualizationreview.com/articles/2026/09/28/openai-to-retire-custom-gpts-replace-them-with-plugins.aspx); [Harvard HUIT](https://www.huit.harvard.edu/news/2026/09/openai-will-retire-custom-gpt-functionality-chatgpt); [THE Journal](https://thejournal.com/articles/2026/10/05/openai-getting-rid-of-custom-gpts-and-moving-to-plugin-architecture.aspx); [SiteSpeakAI](https://sitespeak.ai/blog/custom-gpt-retirement-plugin-migration)
- Simon Willison's workaround before project memory: archive silly conversations so they are excluded from future context, or turn memory off. — [Simon Willison](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- In a user study, participants preferred project-scoped memory over personal memory, and some said they would use temporary chats or disable memory for certain tasks. — [arXiv 2607.07480 via search synthesis](https://arxiv.org/pdf/2607.07480)

### Inferences
- OpenAI's isolation model is scope-based (global, project, ephemeral) rather than per-fact permissions. The default is maximal sharing, and isolation is opt-in.
- GPTs were the "persona + instructions without user memory" container. Their replacement by plugins and skills suggests OpenAI is splitting persona/instructions (skills) from user memory (global or project).

### Gaps
- Whether project-only memory writes new saved memories, and whether those are visible globally, was not confirmed.
- It is unclear whether "Personalized" Temporary Chat reads Dreaming-era User Knowledge Memories or only saved memories.
- It is unknown whether 2026 plugins/skills can access user memory.

## 7. Documented failure modes of personalization

### Takeaway
Documented failures cluster into six groups:
- Irrelevant memory surfacing (location signs in images, wedding rings).
- Stale or wrong memories that are hard to dislodge (old jobs, abandoned plans).
- Opaque inferred profiles users cannot audit, plus shifting summaries.
- Silent "memory full" overwrites.
- Memory amplifying sycophancy.
- Security problems: prompt-injected memories and metadata.

OpenAI's 2026 Dreaming release explicitly names staleness and correctness as the problems it targets. Its own eval implies the old system got memory-dependent facts wrong more than half the time.

### Cited Findings
- Irrelevant surfacing: Simon Willison asked for his dog in a pelican costume, and the image added a "Half Moon Bay" sign drawn from memory. He had to ask it to "ditch the sign". Memory also contaminated his location-guessing experiment. His view: controlling context is "the entire game", and the summary is added "without my explicit permission or control". — [Simon Willison, May 21, 2025](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- Axios reported a user whose image request included a wedding ring although he was no longer married. — [Axios, July 11, 2025](https://www.axios.com/2025/07/11/chatgpt-memory-update) (article 403, details via search synthesis)
- Wrong facts stick: ZDNet testing found "once incorrect information enters ChatGPT's memory, it becomes surprisingly difficult to dislodge", and most users don't audit stored memories. — [TechBuzz summarizing ZDNet](https://www.techbuzz.ai/articles/chatgpt-s-memory-feature-silently-poisons-answers-with-bad-data)
- Stale profile: User Knowledge Memories include outdated facts, "trips that never happened and abandoned projects", because ChatGPT can't detect when plans change. — [Shlok Khemani, Sept 2025](https://www.shloked.com/writing/chatgpt-memory-bitter-lesson). The old memory was "a glorified sticky note" where an old job title stayed "Locked in forever", and errors were delivered confidently. — [The Neuron, June 2026](https://www.theneurondaily.com/p/chatgpt-admitted-its-memory-was-broken). Factual recall was 41.5% for the 2024 system per OpenAI's eval. — same
- Stale memory "feels worse than no memory" because it gives an illusion of familiarity. OpenAI's June 2026 note names stale and contradictory memories as targets. — [Webiano](https://webiano.digital/chatgpt-memory-summary-turns-personalization-into-something-users-can-inspect/)
- Memory Summary problems (2026): each regeneration shows a different partial subset, edits land in chat history rather than the active profile, there is no change tracking, and the summary never reaches context, so control is indirect. "doesn't make me trust ChatGPT's memory more than I did before." — [Shlok Khemani, June 2026](https://www.shloked.com/chatgpt-memory-2026)
- Memory full: new memories fail to save or overwrite old ones, "Memory updated" appears with nothing saved, and older memories vanish without notice. There is no export of saved memories. (Vendor blog, user reports.) — [Unmarkdown](https://unmarkdown.com/blog/chatgpt-memory-full)
- Sycophancy: in the April 25, 2025 GPT-4o update (rolled back about four days later), OpenAI said "user memory contributes to exacerbating the effects of sycophancy, although we don't have evidence that it broadly increases it". The thumbs-up/down reward signal "can sometimes favor more agreeable responses". — [Simon Willison, May 2, 2025](https://simonwillison.net/2025/May/2/what-we-missed-with-sycophancy/); [Georgetown Tech Institute brief](https://www.law.georgetown.edu/tech-institute/research-insights/insights/tech-brief-ai-sycophancy-openai-2/)
- Privacy and agency: 96% of memories were system-created, 28% contained GDPR personal data, and 52% contained psychological inferences. — [arXiv 2602.01450](https://arxiv.org/abs/2602.01450)
- Security: memory poisoning through indirect prompt injection into the `bio` tool. — [Embrace The Red, 2024](https://embracethered.com/blog/posts/2024/chatgpt-hacking-memories/). Memory used to bypass image safeguards. — [Mindgard](https://mindgard.ai/blog/bypassing-image-safeguards-in-chatgpt). Summary and metadata (user agent) injection vectors. — [Embrace The Red, May 2025](https://embracethered.com/blog/posts/2025/chatgpt-how-does-chat-history-memory-preferences-work/)
- **UNOFFICIAL:** metadata includes an internal classifier with lines such as "460 messages are good interaction quality (36%); 420 messages are bad interaction quality (33%)". The leaker speculates this is for training, and its meaning is unknown. It also contained contradictions such as "User is active 2 days in the last 1 day". — [asgeirtj/system_prompts_leaks: tool-advanced-memory.md](https://raw.githubusercontent.com/asgeirtj/system_prompts_leaks/HEAD/OpenAI/tool-advanced-memory.md)
- Project-only memory leakage: some users report general memories "bleeding" into project-only projects. — [Unite.AI](https://www.unite.ai/how-to-use-chatgpts-project-memory/)
- Over-emoji and tone complaints led to user-facing sliders. OpenAI said: "These changes respond to user feedback about ChatGPT sounding either overly friendly or too impersonal." — [WinBuzzer](https://winbuzzer.com/2025/12/22/openai-adds-warmth-and-enthusiasm-sliders-to-chatgpt-delays-adult-mode-to-2026-xcxwbn/); [OpenAI Community](https://community.openai.com/t/how-i-can-turn-off-emojis/1116532)

### Inferences
- The mitigations OpenAI layered on are, in order:
  - Relevance gating in the prompt ("not relevant to 99% of requests"; acknowledge only if directly related).
  - Penalties for using unrelated context.
  - Scope isolation (project-only, temporary).
  - Background correction of stale facts (Dreaming).
  - Inspection UIs (Memory Summary, sort/search).
  - Explicit tone knobs replacing implicit drift.
- Those are the levers any personalized bot needs. Even so, the most persistent complaint is staleness: users rarely announce that a fact has changed.

### Gaps
- No quantitative OpenAI data on how often memory surfaces inappropriately was found.
- The widely reported early-2025 "memories disappearing" incidents were not verified from a primary or detailed source; the Yahoo guide found covers settings only.
- Every's "Why I Turned Off ChatGPT's Memory" ([Every](https://every.to/also-true-for-humans/why-i-turned-off-chatgpt-s-memory)) was found but not read, so its specific complaints are not included.
